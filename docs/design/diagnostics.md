# 日志与诊断包

Cage 将界面、后台、原生窗口和受管子进程的故障记录到本机，便于在故障发生后定位原因。用户从“设置 → 环境与恢复 → 日志与诊断”导出 ZIP；应用无法打开时可使用命令行。日志和诊断包均保存在本机，不自动上传。

## 收集范围

| 来源 | 记录内容 |
|---|---|
| 控制服务 | 启动、退出、标准输出、错误输出、异常堆栈 |
| 后台任务 | 操作开始、完成、取消或失败，以及管理操作输出；界面保留末尾约 24 KB |
| 工作台接口 | 错误状态与路由模板、主动返回的错误、处理器异常；不记录请求正文和认证头 |
| 工作台界面 | 全局脚本异常、未处理的 Promise 拒绝、React 渲染异常、接口连接失败和原生调用失败 |
| 原生窗口 | 启动、导航、WebView 进程异常、桥调用和更新失败；通过本机辅助程序写入同一存储 |
| 内置代理 | 配置校验错误、运行输出和非正常退出 |
| 虚拟机 | 主机代理的诊断输出，以及 Cage 浏览器、编辑器、显示、音频和 Desktop 服务输出 |

终端输入输出、项目文件、剪贴板内容、请求正文、完整配置、浏览历史和登录数据库不作为诊断材料采集。底层虚拟机的串口文件、生命周期协议文件，以及第三方应用自行保存的日志不属于 Cage 诊断存储，也不自动收入诊断包。

## 脱敏与存储

主机日志使用私有配置目录下的 `logs/`，记录格式为 JSONL，包含 UTC 时间、级别、来源、消息和进程号。Unix 文件使用 `0600`、目录使用 `0700`；Windows 沿用仅当前用户与 SYSTEM 可访问的 DACL。

写入前遮盖凭据字段、认证与 Cookie 头、常见 API 密钥和令牌、私钥、网址、邮箱、IP 地址及常见本机文件路径。子进程输出先组合成完整行，再执行脱敏；跨多次写入的密钥仍按同一行处理。超过 24 KiB 的单行整行省略，私钥块整段省略。导出时再次脱敏。自动规则无法识别所有自由文本中的敏感信息，分享前仍应检查诊断包。

| 存储 | 保留与清理 |
|---|---|
| 本机统一日志 | 最多保留 14 天、总容量 40 MiB，单文件约 5 MiB；跨天或达到大小上限时轮转，优先删除最旧文件 |
| 客机 Cage 服务日志 | 独立的 `cage` journal namespace，预算 10 MiB、保留 14 天；服务输出使用与主机相同的脱敏规则，再交给 journald |

主机在服务启动、日志写入、查询容量、导出及每小时执行清理，多个进程通过系统文件锁协调写入和轮转。日志时间以文件中最早的事件校验，持续使用的小文件也会到期。应用关闭期间不运行清理，下一次启动时补清。客机由 journald 管理归档及清理，实际占用可能受活动 journal 文件和文件系统开销影响。

旧的后台、代理和安装日志在服务启动时迁入统一存储：只读取有限尾部，脱敏后删除原始文件；超过保留期限的旧文件直接清理。Cage 安装过程直接写入统一日志。上游 agent-vm 独立使用时保留其原有日志行为。

## 导出与故障恢复

三端桌面程序提供本机保存窗口，取消后不生成诊断包。保存先写同目录私有临时文件，完成校验后替换目标文件，失败时保留已有目标。普通浏览器使用文件下载。诊断包生成期间不修改环境或停止任务。

ZIP 只包含固定范围的文件：

- `manifest.json`：格式版本、应用版本、操作系统、架构、Go 版本、日志策略和客机收集结果。
- `logs/*.jsonl`：仍在保留范围内的脱敏主机日志。
- `guest/services.log`：客机可访问时，收集最近 150 行 Cage 服务日志，最多 48 KiB。
- `README.txt`：内容范围与分享前检查说明。

客机收集设置超时；离线或读取失败时，诊断包仍包含主机日志，清单记录缺失原因。命令行入口为 `cage diagnostics --json /absolute/path/cage-diagnostics.zip`。它通过本机启动凭证连接控制服务；控制服务不可用或启动记录损坏时直接导出本机日志。

前端每分钟最多接受 20 条上报，队列最多 20 条，单条消息最多 4096 个字符。后台暂时断开时每 5 秒尝试补报；关闭或崩溃的页面无法保留内存队列。服务端每分钟最多接受 60 条界面上报。日志失败不替代原始错误，断电、磁盘不可写、强制终止等情形仍可能丢失最后一段记录。

## 接口与平台职责

| 入口 | 行为 |
|---|---|
| `GET /api/diagnostics` | 返回保留策略、本机容量及文件数 |
| `POST /api/diagnostics/events` | 接受 `frontend`、`react` 来源；限制正文 32 KiB，不接收文件路径 |
| `GET /api/diagnostics/export` | 返回完整 ZIP；同一服务只允许同时生成一份 |
| 原生 `exportDiagnostics` | 本机保存窗口，再调用统一 CLI；网页不能指定任意保存路径 |
| `cage diagnostic-event` | 从标准输入接收原生错误，写入前脱敏 |
| `cage log-relay controller\|proxy` | 在子进程外收集输出，控制服务异常退出时仍能保存故障信息 |

HTTP 入口沿用工作台的 Host、Origin、会话认证。诊断接口允许持有效工作台会话的锁定页面使用，使登录界面的异常也能记录；不返回账户、代理或项目配置。原生桥继续只接受当前工作台主框架。macOS 的 launchd 通过输出中继启动代理；Windows、Linux 在原有进程身份校验和停止流程下收集代理输出。

客机日志配置随环境组件更新部署。已有运行环境需先保存浏览器和编辑器中的修改，再使用现有的组件更新流程；应用不会为启用日志而静默重启环境。
