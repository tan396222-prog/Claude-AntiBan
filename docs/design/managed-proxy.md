# Cage 内置代理

本文说明 Cage 内置代理的产品范围和工程边界。应用随附独立核心，管理订阅、节点和代理生命周期；客机公网 UDP、IPv6、ICMP 持续阻断。联网授权规则见[网络检测设计](network-checks.md)，界面入口见[工作台设计](workbench.md)。发行版本的验证范围以 GitHub Release 说明为准；本地验收截图和原始运行数据不随源码发布。

## 用户怎样使用

用户安装 Cage 后，在应用内添加代理订阅或导入本地配置，在节点页选择最终出口，按需添加中转并点击「应用代理」，检查出口后启动环境。浏览器、终端、Claude Code 及其子进程共用 Cage 管理的出口；即使没有安装本机 Clash，仍能完成这一过程。

代理页提供已配置节点、最近检测出口、核心状态及连接反馈。用户更换节点后，旧连接结束，新节点通过检查才恢复对外联网；终端进程和项目文件保留。修改本地端口时需要重启环境，界面提前提示终端中断。代理不可用时明确显示离线原因和重试入口，不回退主机直连。

## 首版基本功能

| 入口 | 用户可完成的操作 | 失败和恢复 |
|---|---|---|
| 订阅 | 添加多个订阅、修改名称、手动更新、设置定期更新、删除；有服务端数据时显示流量与到期信息 | 更新失败保留最后可用版本，展示失败原因和更新时间；删除当前来源时要求另选节点或保持离线 |
| 本地导入 | 导入 Clash/Mihomo YAML 完整配置或节点集合；手动添加 HTTP/SOCKS5 节点 | 显示格式及协议兼容性错误；不借助第三方在线转换服务上传订阅凭据 |
| 节点 | 按来源查看和搜索，选择单节点或组合中转与最终出口，预览后统一应用；支持单节点或批量延迟检测 | 草稿未应用时不改变当前网络；配置验证或核心启动失败保留草稿和原配置；出口检查失败保留新配置并关闭外网；离开设置前确认是否放弃；延迟成功不代表环境已放行 |
| 连接状态 | 查看核心是否就绪、当前实际节点、出口 IP/地区、实时速率和本次流量 | 区分核心未启动、节点连接失败、环境检查未通过及主动暂停 |
| 诊断 | 查看连接和状态摘要，停止或重启 Cage 自己的核心，配置独立端口 | 不操作本机其他代理实例；重启期间关闭 Cage 外网；核心原始日志保存在私有目录，不向页面公开 |

订阅支持含 `proxies` 或 `payload` 的 Clash/Mihomo YAML，也接受含内联节点的完整配置。只含远程 provider 的配置、Base64 列表和各类分享链接暂不支持，需提供节点订阅地址或先导出 YAML。支持 HTTP、SOCKS5、SS、SSR、VMess、VLESS、Trojan、Hysteria、Hysteria2、TUIC、AnyTLS、Mieru；Mieru 可使用 TCP/UDP 传输、端口范围、复用、握手模式和流量模式参数，具体字段仍须由固定版本核心校验。导入内容里的代理链必须引用同一来源内的具体节点，选择分组和 DIRECT 链路会被拒绝。界面配置的代理链可以组合不同来源的节点。

### 在界面中配置代理链

住宅代理无法从国内直接连接时，在「节点」页选择「链式代理」，将国内可连接的代理设为中转，将住宅代理设为最终出口。列表按流量顺序展示，例如「Cage → 中转节点 → 住宅代理 → 目标网站」。最终出口决定目标网站看到的 IP；节点名称与协议不能证明其出口属于住宅网络。可继续添加中转，节点不得重复。下拉选项在容器内展开，撑开页面；支持键盘选择与收起。

节点列表用于选择最终出口，修改后须点击「应用代理」生效。配置区、当前链路摘要分别显示草稿与已保存的配置，修改期间当前链路继续工作。应用前会验证整条链路的配置；生效时沿用关闭旧连接、更新配置版本与重新检查出口的流程。配置验证或核心启动失败时保留原有保存配置，核心启动失败后可能处于停止状态，需要重试。新配置启动后若出口检查失败，保留新配置并关闭业务外网，待修复后重新检测；不因此直连或绕过中转。订阅参数校验通过与核心启动成功均不代表远端链路连通，仍须检查实际出口。

界面代理链以可选的 `chain` 节点 ID 列表独立保存，按入口到出口排序，`selected` 指向最后一跳。生成运行配置时，复制节点字段并按顺序覆盖每一跳的 `dialer-proxy`，第一跳清除原有前置代理；订阅原文和凭据保持不变。单节点模式显式保存一个节点并清除该节点原有前置代理。旧配置没有 `chain` 时继续遵循已导入的代理链，状态接口返回其实际顺序。

订阅更新按稳定节点 ID 保留界面链路。如果更新移除了链路中的节点，拒绝该更新并保留最后可用来源；删除多节点链路正在使用的来源时，要求先应用其他配置。已明确选择单节点时可删除其来源，随后停止代理并保持离线。不会静默删掉中转或更换最终出口。

每份导入内容最多 8 MiB，全部来源保存后的 JSON 总量最多 32 MiB。累计超限时拒绝保存并保留原文件，用户仍可查看或删除已有来源。

默认手动选择固定节点，与现有出口 IP 变化规则协作。自动测速可以提供建议；自动切换和负载均衡涉及出口变化，需单独设计准入流程，首版不静默启用。

节点列表和工作台状态栏共用 HTTPS `www.gstatic.com/generate_204` 延迟检测，核心固定开启 `unified-delay`。第二次 HEAD 请求成功时，显示已建立连接上的 HTTP 往返耗时；首次建连和握手仍会发生，但不计入该数值。核心在第二次请求失败时会回退首轮计时，因此界面说明为“通常不含建连开销”。延迟不代表带宽、网页首开耗时或环境已经放行。核心就绪检查同时核对这一设置，旧口径的运行实例需在应用代理时重新生成配置并启动。

## 流量与模块职责

```text
Cage 浏览器 / 终端 / 开发工具
                  ↓
       VM 外网络约束与联网检查
                  ↓
      Cage 专属本地代理监听端口
                  ↓
      Cage 随附的 Mihomo 独立进程
                  ↓
           用户选定的代理节点
                  ↓
               互联网

Cage 代理管理界面 → 已认证的 Cage 控制服务 → 私有控制 socket
```

复用现有 VM 外网络出口接管流量。该边界覆盖不遵循 HTTP_PROXY 等环境变量的程序；项目内程序不能自行关闭这层约束。SSH、显示及文件共享保留现有内部管理通道。

Mihomo 以随 App 分发的独立进程运行，由 Cage 控制服务负责启动、就绪检查、停止和配置切换；故障后用户可以重新应用节点或重启核心。运行不引用 `/Applications/Clash Verge.app`，不搜索 PATH。构建固定 `v1.19.33`，校验官方发布压缩包的 SHA-256，并将来源与 GPL-3.0 许可资料放入制品。工作台或 App 窗口关闭而环境保留运行时，独立 launchd 任务继续提供代理；明确停止环境会停止该核心。

Linux 将核心作为普通用户的独立后台进程运行，窗口关闭后继续提供代理。私有进程记录包含可执行文件、启动时间与系统启动标识；停止前用 pidfd 固定并核验进程身份，避免误停复用同一 PID 的其他程序。Linux 根据 IPv4 默认路由与物理设备归属选择 PCI、USB 或 virtio 网卡，排除隧道、桥接和容器 veth；找不到符合条件的出口时保持离线。实现需要 Linux 5.3 或更新内核。

前端继续使用 Cage 现有认证接口，不直接持有核心控制权限。核心控制 socket 放在主机私有目录，guest 无法访问；订阅 URL、节点凭据和完整配置同样不进入共享项目、普通日志或状态接口。socket 的目录和文件权限必须落实，不能依赖核心 HTTP secret 保护 Unix socket。

导入内容只提供节点、必要的代理链和来源信息；Cage 自己生成运行配置。外部配置不能覆盖监听端口、控制接口、TUN、DNS 边界、文件路径或全局出站规则。Cage 业务流量统一走选定节点，不引入订阅中的 DIRECT 回退规则。

## 依赖安装与更新

Cage 的环境组件同步、固定工具升级和 Claude Desktop 安装需要在业务网络尚未放行时下载依赖。这些操作使用短时维护通道：固定安装脚本经 SSH 连接主机上的认证代理，再通过当前所选节点访问软件源。维护操作不授予业务联网权限，不解除人工暂停，也不向普通终端注入代理凭据。

维护代理只接受 Debian、NodeSource、GitHub 发布文件、npm、Anthropic 下载服务和 Cage 选用的国内镜像域名。HTTP 请求限于 80 端口的 GET/HEAD，HTTPS 隧道按目标域名和 443 端口授权。APT 按 Debian 官方签名索引中的摘要验证从南大、中科大下载的 Chromium 安全更新包。来自中科大的 code-server 和来自 npmmirror 的 mise 采用 Cage 固定的归档摘要，npmmirror 上的 Claude Code 可执行包采用 npm 官方提供的完整性摘要。各安装器负责校验隧道内下载的内容。临时凭据经 SSH 标准输入传递，任务结束、失败或取消时关闭连接并清理凭据。三个平台共用这条路径，所选代理不可用时下载失败。

## 与本机 Clash 共存

使用独立配置、缓存、日志、进程和监听地址，仅绑定 loopback。默认沿用 Cage 专用端口 `17896`，占用时给出冲突提示并允许配置其他端口；不终止占用者，也不连接来源未知的现有监听器。代理入口采用 Cage 私有认证。

Cage 不设置主机系统代理，不开启主机 TUN，不修改本机 Clash 的节点选择。退出和停止只处理 Cage 自己的进程；用户选择保留环境运行时，对应代理也必须保留。

代理启动时，Cage 根据 macOS 的硬件端口、IPv4 可达状态和默认路由选择当前物理网卡，并绑定代理核心到该网卡。默认路由指向 TUN 时，按系统报告的网络优先级选择可达的物理网卡。未找到可用物理网卡时保持外网关闭，不启用未绑定的代理路径。此规则适用于 Cage 自带核心；用户在 Cage 外运行的代理进程不属于其生命周期。

控制服务约每 5 秒检查一次物理网卡。发现网卡变化或检测到断网后恢复时，先撤销现有联网授权，再重启 Cage 专用代理、绑定当前网卡并重新执行完整检查。原 VM、终端和共享文件保留；代理节点、静态 IP 和地区基准不变。用户手动暂停过外网时只更新代理绑定，恢复联网仍需用户重新检测。相同网卡上未被采样发现的短暂断网，由代理的连接重建和现有出口监测处理。

物理网卡绑定约束 Cage 代理核心的宿主传输路径；客机仍只能连接指定代理，公网 UDP、IPv6 和 ICMP 的限制不变。绑定效果需要在实际 macOS 路由和 VPN 环境中验证，不能据此推导整台宿主机的所有进程均已绕过 VPN。

## 订阅和节点域名的启动依赖

Cage 业务 DNS 继续通过选定节点发送，不回退主机解析器。订阅下载、首次节点服务器域名解析属于代理自身的启动通信，需要与业务流量分开说明。

订阅默认经当前配置的代理下载；没有节点时可导入本地文件，或明确选择通过主机网络下载。手动更新提供相同的主机下载选项；自动更新始终使用已配置代理，失败后至少间隔 15 分钟重试。下载只接受 HTTPS，限制大小和重定向次数，不静默切换路径，不调用本机 Clash 接口。

主机下载的域名和核心节点服务器域名使用两个 IP 定位的加密 DNS：Cloudflare `https://1.1.1.1/dns-query` 和[阿里公共 DNS](https://static-aliyun-doc.oss-cn-hangzhou.aliyuncs.com/download%2Fpdf%2F171662%2FAPI_Reference_intl_en-US.pdf) `https://223.5.5.5/dns-query`。二者并行查询，单个服务不可达不会阻塞另一个；主机下载的启动解析最多等待 8 秒，收到有效公网 IPv4 后取消其余请求。节点域名解析由 Mihomo 的多服务器解析器执行。这部分通信通过主机网络，域名可能发送给两个 DNS 服务，独立于业务 DNS；状态和诊断页面列出这两个服务。两者失败时不回退系统 DNS、明文 DNS 或未经验证的 TLS 连接。客机业务 DNS 仍经选定节点发送。

## 节点切换与检查

节点和订阅更新由同一控制服务串行应用，避免并发更新覆盖用户刚选的节点。应用前保存可恢复配置并验证候选内容；失败保留原版本。

自动订阅更新和物理网卡恢复会保留用户手动暂停外网的状态。人工代理操作可以按现有流程重新检查并恢复联网；如果用户在下载订阅或应用核心期间再次暂停，较新的暂停优先，操作完成后仍保持离线。

生效切换先关闭现有联网授权并断开旧业务连接，再应用新节点、检查核心实际选择，最后重新执行准入。代理配置的 `proxy_revision` 随切换和核心重启更新，纳入配置指纹。VM 外门槛只允许在其余配置相同的条件下更新该版本，同时撤销旧报告和连接；地址、DNS、语言等变化仍需重启 VM。界面分别显示尚未配置、尚未应用、代理已停止、待启动环境、正在检查和外网未放行；只有当前节点已应用、核心读回匹配且 VM 放行仍有效时才显示已联网。

手动切换不能悄悄改写已绑定的静态 IP 或地区基准。新节点不符合用户保存的出口规则时保持离线，引导用户另选节点或明确修改规则。

## 协议范围

当前只允许客机公网 IPv4 TCP，DNS 经相同代理发送 DoH；公网 UDP、IPv6 和 ICMP 均阻断。随附 Mihomo 本身支持某种协议，不代表客机出口已经接通该协议。

客机 UDP、IPv6 和 ICMP 保持阻断，不因选用支持这些协议的节点而开放。核心到代理服务器的传输协议由节点决定，例如 Hysteria 的传输可使用 UDP；这不构成客机任意 UDP 出站通道。

## 接入点与验收

`internal/managedproxy` 维护来源、运行配置、下载与核心控制；`internal/cage/egress.go` 及网络准入负责业务出口；`internal/workbench/proxy.go` 承接经工作台认证的管理接口；`ui/src/proxy-settings.jsx` 提供节点、订阅、连接及诊断页面。`scripts/fetch-proxy-core.sh` 固定核心制品，`scripts/build-app.sh` 将其随 App 分发。节点管理器是唯一出口配置来源，网络设置仅提供加密 DNS，不接受手工指定本地出口地址。`proxy_url` 与 `proxy_revision` 是管理器生成的内部字段，通用设置和配置恢复无法覆盖它们。未选节点、未应用或配置版本不一致时，启动、探测和网络授权均拒绝放行。

来源与核心操作使用工作台已有的串行任务机制。管理接口包括 `GET /api/proxy`、`POST /api/proxy/{import,refresh,edit,delete,select,route,restart,stop}`、`POST /api/proxy/delay` 及连接和诊断摘要的 GET 接口。前端不能传入任意核心控制路径。订阅 URL、认证和节点原始参数只存在私有来源文件中，GET 状态只返回来源主机名、节点显示信息与脱敏的有序 `route` 节点 ID。`route` 操作以 `node_ids` 提交完整链路，统一校验并应用；不会逐个修改已在使用的节点。

验收必须覆盖：未安装 Clash 时从导入到客机联网；与本机 Clash 系统代理/TUN 分别共存；订阅更新失败与选中节点被移除；真实节点切换后旧连接关闭、旧报告失效；核心崩溃后业务和 DNS 均无直连回退；App 停止、退出、保留运行和重新进入；凭据及管理接口未向 guest 暴露。模拟测试和核心延迟测试不能代替这些安装版路径。
