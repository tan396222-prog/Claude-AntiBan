# 控制服务的职责与资源归属

本文面向修改工作台后端的维护者，用于定位业务操作、连接和退出流程。用户操作及界面约定见[工作台设计](workbench.md)，联网授权见[网络检查设计](network-checks.md)，代理进程与凭据见[内置代理设计](managed-proxy.md)。

## 调用关系

桌面窗口加载 React 工作台。工作台通过本机受认证的 HTTP、WebSocket 和 SSE 接口调用控制服务；控制服务协调同一份配置的持久 VM、项目共享、终端与浏览器。客机中的网页、编辑器和终端进程不获得主机管理接口的凭据。

远程模式由本地连接服务提供应用自带的工作台，再通过 SSH 转发业务接口。云端控制服务协调持久容器、服务器项目与网络门槛，桌面断开连接后云端任务继续。两端的身份边界见[云端部署设计](cloud-deployment.md)。桌面连接服务的退出条件以及本机控制服务按需启动、按状态回收的方案见[桌面入口与资源设计](desktop-environments.md)。

`internal/workbench/` 内的入口按职责组织，服务接口保持包内可见。当前只有工作台调用这些服务，尚未引入新的界面框架或公共 SDK。

| 位置 | 负责什么 | 由谁持有资源 |
| --- | --- | --- |
| `server.go`、`control_lifecycle.go` | 监听、认证、路由、控制身份与空闲接管 | 控制服务持有配置锁和监听器 |
| `lifecycle.go`、`lifecycle_http.go` | 请求准入、服务取消、活动等待和受控退出 | 控制服务持有生命周期与请求计数 |
| `jobs.go` | 作业准入、串行执行、取消、进度与结果 | 作业管理器持有执行上下文；细节见[作业约定](workbench.md#作业与后台监测) |
| `jobs_service.go`、`jobs_http.go` | 联网意图与账户完成规则、HTTP 响应 | 工作台保存业务状态；HTTP 返回作业快照 |
| `terminal_service.go`、`terminal_session.go` | 会话创建、容量、进程回收、历史输出和订阅 | 终端管理器持有 PTY，会话持有输入队列、读写循环与订阅 |
| `terminal.go`、`websocket.go` | 终端协议、WebSocket 升级与请求取消 | 每个请求持有自己的显示连接 |
| `browser_client.go`、`browser_service.go` | 客机控制运输、就绪状态、项目授权和宿主路径转换 | 浏览器客户端持有 HTTP 连接池，每个响应持有取消资源 |
| `browser_http.go`、`browser_files.go`、`browser_workspaces.go` | 浏览器动作、文件流和事件快照的 HTTP 适配 | 请求持有响应体与订阅，客机服务持有浏览器进程 |
| `vnc.go`、`audio.go` | 远程画面与声音传输 | 显示请求持有主机连接、读写循环及临时 SSH 进程 |
| `projects.go` | 已授权目录、共享记录、SFTP 连接及错误状态 | 控制服务持有共享连接，具体目录仍由项目授权限定 |
| `runtime.go`、`safety.go`、`proxy.go` | 环境操作、网络检查与代理业务协调 | 仍使用现有 VM、网络门槛与受管代理实现 |

HTTP 层解析输入和映射状态码，工作台业务层核对授权、配置和环境状态，资源拥有者负责取消与清理。自动代理恢复与订阅刷新直接使用作业提交入口。

## 关闭的范围

关闭终端查看连接只释放该连接与订阅；会话继续接收输出，重连从保存的历史与实时输出继续。历史快照和订阅注册在同一把锁下完成，避免重连时遗漏夹在两者之间的数据。慢订阅者会被断开，不阻塞其他终端用户。删除终端或停止环境会关闭 PTY，并等待读写循环和主机进程结束。

终端输入由会话按接收顺序写入 PTY，查看连接不阻塞在底层写入上。输入队列满时断开当前查看连接，已经接受的输入继续由会话处理；停止会话会取消尚未写入的排队输入。因此，客机暂时不读取输入时，关闭页面或锁定账户仍能及时释放查看连接。

浏览器客户端只连接固定的客机控制地址，不使用主机 HTTP 代理，也不跟随重定向。短操作、事件订阅和文件传输共用运输边界，分别采用对应期限。取消某个订阅只释放该响应；关闭客户端会取消全部在途操作并释放空闲连接，客机浏览器的登录资料和进程不由客户端销毁。

声音和远程画面请求结束前，先关闭底层传输解除阻塞，再等待传输循环退出。画面输入使用有界队列；客机持续拒绝接收输入时断开当前画面连接，避免无限积压。关闭窗口、锁定账户和服务退出通过请求取消触发这些清理。

## 受控退出顺序

控制服务受控退出时，按以下顺序释放主机资源：

1. 封闭请求与作业准入，取消服务生命周期及在途检查。
2. 封闭终端创建，关闭已有 PTY，解除可能阻塞的输入写入。
3. 取消作业，等待作业、监测和活动请求完成。请求结束包括其订阅、传输循环和临时进程的清理。
4. 取得操作锁，停止项目共享并等待其子进程；释放浏览器空闲连接，关闭网络门槛并停止受管代理。
5. 清除已发布的控制记录，由入口释放配置锁。

该流程不调用 VM 停止命令，保留磁盘、环境身份、项目授权和持久联网意图。应用窗口关闭不退出控制服务。用户执行“停止环境”仍由现有环境操作停止 VM；版本接管仍要求没有运行环境、作业和存活终端。

等待不能发生在请求准入锁内，也不能由持有操作锁的接管请求等待自身退出。接管确认响应具有明确长度，发送后释放操作锁，再异步启动关闭流程。

## 平台与构建边界

macOS/Linux 继续使用 Unix PTY，Windows 继续使用 ConPTY。Unix 主端使用可中断读写的描述符，调整尺寸不切回阻塞模式；主机进程结束后，若后代仍持有 PTY 且主端尚未收到 EOF，会话继续接收输出，明确关闭会释放主端并等待会话回收。工作台不新增杀死进程树的规则。

控制锁、路径映射、隐藏进程窗口和代理进程继续由现有平台实现负责。客机脚本仍位于 `internal/cage/`，构建与发布脚本仍位于 `scripts/`，嵌入资源、CI 和安装器沿用当前入口。职责拆分不改变发布版本或签名策略。
