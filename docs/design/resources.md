# 计算资源与压力恢复

Cage 按环境内程序的需求调整可用内存。浏览器、编辑器、终端和渲染任务共享同一虚拟机；任务结束后，持续空闲的内存逐步归还主机。资源上限遵循主机份额政策，默认使用一半物理内存及一半逻辑 CPU；小内存机器的内存上限最低为 2 GiB，CPU 最低为一个核心。现有 `AGENT_VM_HOST_SHARE` 覆盖规则继续适用，无法读取主机配置时使用 4 GiB、2 CPU。

CPU 的实际使用时间由主机调度器按负载分配。配置的核心数约束最大并行度，空闲时无需持续占满这些核心。内存的启动容量、当前分配目标、客机可用容量和主机实际占用是不同指标；设置页分别展示上限和客机观测，主机活动监视器还包括虚拟化开销与系统内存管理的影响。

## 用户操作

“设置 → 环境与恢复 → 计算资源”显示自动上限、环境内存用量、当前可用容量、CPU 使用率及本次启动后的系统 OOM 终止计数。内存用量不含可回收缓存。采样失败显示未知，不以过期数据表示正常运行。

Claude Desktop 服务因 OOM 退出时，应用页直接显示内存不足及检查计算资源的提示。状态读取暂时失败与用户操作失败分别保存；下一次读取成功清除读取错误，操作失败仍保留供用户处理。

新环境及已停止环境在启动时应用主机份额。已经运行的环境保持原启动容量；需要提高容量或加载新控制逻辑时，用户点击“重启并应用自动资源配置”，确认保存后重启。正在运行的命令会结束，项目文件、虚拟磁盘和登录资料保留。重启不解除手动暂停网络的状态。

自动分配仍受主机容量限制。持续超出上限的任务可能失败；减少并行渲染、降低任务规模或使用内存更多的机器才会降低其实际资源需求。137 是常见的强制终止退出码，不能单独证明 OOM。诊断中出现同一时段 OOM 计数增加，才是客机发生内存不足终止的直接证据之一。

## 控制位置与平台

```text
客机系统指标 → 虚拟机主机后台 → 内存分配目标 → 平台虚拟化设备
                       ↓
                  私有状态与日志 → 工作台资源页面
```

资源循环属于虚拟机的主机后台，与 VM 同生共灭。关闭界面不会停止内存调节，停止 VM 前取消采样并等待控制循环结束。控制能力不暴露给客机，客机观测只能影响既定上限内的分配，不能修改主机份额或其他 VM。

| 平台 | 调整机制 | 当前边界 |
|---|---|---|
| macOS | Apple Virtualization 的传统 Virtio balloon | 目标不得超过启动容量；宿主处于严重内存压力时暂缓增长 |
| Windows | QEMU balloon 命令，经本机 QMP socket | 同样受启动容量约束；采样子进程不弹出控制台 |
| Linux | QEMU balloon 命令，经本机 QMP socket | 同样受启动容量约束；客机采用共同的 Linux 指标 |

三平台共享策略、状态格式和设置界面；平台编译通过不能代替实机回收测量。Windows 当前运行独立 QEMU，WSL 的自动回收设置不适用于 Cage。

## 调整策略

后台约每两秒通过现有私有 SSH 通道读取内存、交换区、CPU、内存等待时间和 OOM 计数。单次读取限定三秒、16 KiB，不采集命令内容、项目文件或进程参数。

内存紧张时立即请求恢复到启动上限；一般增长保留至少 1 GiB 或活动内存四分之一的余量。只有余量持续充足 30 秒，才按每次 256 MiB 逐步回收。Linux balloon 计数用于确认上一次回收已经完成，并从客机用量中排除已经归还的页面；不同内核是否同步减少 MemTotal 不影响这一口径。最低目标为 2 GiB，且不超过本次启动上限。

采样失败停止缩容。在主机未出现严重压力时，恢复既定上限，以免客机缺内存到无法执行采样命令。主机严重内存压力优先限制继续增长，仍只回收客机有余量的部分。压缩交换区最多为启用时客机内存的四分之一、且不超过 2 GiB，实际使用时才消耗内存，用于缓冲突发申请；它不能增加物理内存，也不能保证任何任务都不会 OOM。内核不支持压缩交换区时保留资源控制并报告服务失败。

资源摘要保存在 VM 私有目录的 `cage-resources.json`，包括时间、进程标识、上限、目标和系统指标。超过十秒的摘要视为过期。目标调整和 OOM 计数增长写入统一脱敏日志。`GET /api/environment/resources` 返回资源状态；`POST` 提交明确的重启应用操作，沿用工作台认证和任务串行规则。

## 内部断网后的恢复

客机或浏览器无法响应联网监测时，现有出口授权仍会收回。连续监测失联导致授权到期也会关闭已有连接；资源优化不会放松出口、DNS、地区和配置检查。

临时观察失败、代理探测失败或授权续期失败后，后台等待并重新执行完整检查；全部必需项目通过后才恢复联网。失败采用逐步退避，间隔最长五分钟。已观测到资源压力时延后重检，避免额外检查争抢资源。

恢复请求绑定 VM 运行标识、配置、出口授权代次和人工暂停序号。排队期间发生手动暂停、停止、配置改变或另一轮检查，旧恢复请求作废。已读回的配置确实不匹配时，不将它作为临时超时自动恢复。人工暂停始终需要用户明确恢复。详细出口条件见[网络检查设计](network-checks.md)。

## 能力依据

- [Apple balloon 设备](https://developer.apple.com/documentation/virtualization/vzvirtiotraditionalmemoryballoondevice)及[目标容量约束](https://developer.apple.com/documentation/virtualization/vzvirtiotraditionalmemoryballoondevice/targetvirtualmachinememorysize)：运行时调整需客机配合，且受启动容量限制。
- [QEMU balloon 观测](https://www.qemu.org/docs/master/interop/virtio-balloon-stats.html)：客机驱动观测可能不可用或滞后，必须区分请求与实际状态。
- [Linux zram](https://docs.kernel.org/admin-guide/blockdev/zram.html)：压缩块设备、动态创建和交换区启用。
