# Cage 工作台

Cage 面向在本机或自有服务器项目中工作的用户。主界面管理当前工作环境的项目、网页、终端和文件编辑器；设置页集中管理环境配置。界面采用 Codex 桌面端的侧栏与内容区结构，保留 Cage 的名称和图标。每份环境配置提供一个独立账户，不依赖集中式云端账户服务。

工作台左侧的“SSH”在原位打开主机列表，顶部显示当前环境。远程模式保持相同的工作台，项目目录和应用运行在服务器，本地负责原生输入与明确的文件传输。同一桌面入口的启动顺序和本机内存释放方案见[桌面环境切换设计](desktop-environments.md)。下文的虚拟机、主机共享与本机安装说明描述本地运行方式。无 KVM 容器、SSH 连接与两端数据归属见[云服务器部署](cloud-deployment.md)。

## 本地账户与锁定

每份 Cage 配置只有一个本地账户，与同一个持久环境关联。首次使用设置用户名和密码，随后通过密码解锁；左下角显示头像和用户名，菜单提供“设置”“锁定 Cage”和“退出账户”。从该菜单打开设置时默认显示“账户”，可在同一页切换到其他设置分组。头像接受不超过 2 MB 的 PNG/JPEG，在本机居中裁切为 128×128 PNG，资料和密码分别保存。

“锁定 Cage”关闭工作台的终端与画面连接，保留后台进程；重新解锁恢复连接。“退出账户”先停止环境，成功后清除驻留解锁材料。停止失败时保留登录状态并报告错误。退出应用清除内存中的解锁材料，后台任务继续运行；启用记住登录后，再次打开可自动进入。锁定不会撤销运行中应用已持有的令牌。

私有 `account.json` 保存账户资料和加密后的随机内部密钥。密码通过 Argon2id（64 MiB、3 轮、2 路）派生 AES-GCM 包装密钥，修改密码只重新包装同一内部密钥。内部密钥经 SSH stdin 和客机私有 FIFO 交给密钥环，用户密码不传入客机；秘密不写入 URL、命令参数、日志或前端持久存储。启动失败不覆盖已有未知密码的密钥环。

控制接口沿用来源和主机会话校验，并增加账户解锁要求；锁定时取消现有显示连接，异步环境任务不受影响。账户元数据、登录及外观读取可在锁定时访问。账户文件损坏时拒绝启动，避免误建新账户覆盖旧密钥。此功能不加密项目或整个虚拟磁盘，不提供不同操作系统用户之间的额外隔离，也没有在线密码找回。

macOS 的“登录与解锁”提供记住登录与 Touch ID 两项开关。首次创建账户时默认勾选记住登录，用户可取消；手动关闭后不会在后续启动时重新开启。记住登录允许重新打开应用直接进入；手动锁定会持久保存必须验证的状态，即使后台重启也拒绝自动登录。密码或 Touch ID 成功解锁后解除该限制。退出账户撤销所有本机快捷登录凭据，之后需要密码重新开启。

每种快捷登录使用独立随机凭据包装同一个内部密钥。原生启动器通过受认证的本机接口交换凭据，网页只获得状态；后端不接受指纹成功的布尔值作为解锁依据。自动登录凭据保存在本机登录钥匙串，访问受应用代码签名控制；指纹凭据存入 Data Protection Keychain 并使用 `biometryCurrentSet`，必须通过系统指纹验证才能读取。指纹变化、取消、钥匙串不可用时保留密码入口。带指纹功能的构建需要匹配应用标识的 Developer ID 描述文件，构建可通过 `CAGE_PROVISIONING_PROFILE` 指定；缺少系统授权时不会改为不受保护的指纹凭据。

快捷登录开关同时依据账户授权记录与当前目录对应的钥匙串状态。凭据缺失或可检查的凭据标识不匹配时，开关显示为未开启，登录页停止自动尝试并提示使用密码后重新开启。目录迁移不会搜索或转移原目录的凭据。检查过程不读取解锁密钥、不弹出认证窗口、不撤销授权；钥匙串暂时不可访问时显示检查失败并允许重试。受指纹保护的记录可能需要认证才能检查属性，此时保留 Touch ID 入口，凭据标识仍在实际解锁时核验。开启、关闭、失败及账户目录或授权变化后重新检查状态。Windows 和 Linux 返回不支持快捷登录，公共界面保留密码入口。

密码保险箱随本地账户解锁和锁定，提供网站密码保存、选择填充与再次验证后的查看和复制。数据归属、浏览器校验及恢复条件见[密码保险箱设计](password-vault.md)。

## 主界面

Cage 只使用一个持久环境，VM、账户登录态、开发工具和家目录在所有项目间共享。项目对应实际共享的文件夹，左侧项目列表直接读取控制服务保存的目录，包含默认工作区；每个目录下只列出在该目录创建的终端。折叠目录不影响其中的终端进程。

浏览器是独立的应用入口，网页使用内容区顶部的横向标签栏，不归属于项目。点击左侧“浏览器”返回仍在运行的浏览页面，顶部加号与 ⌘T 新建网页。文件编辑器页也在顶部标签栏显示，并在标题中标明打开的目录；打开项目与切换终端均不关闭已有网页。终端内容区显示所属目录及终端名称。

网页标签及标签搜索列表显示 Chromium 已取得的网站图标。客机扩展通过原生图标缓存读取 32×32 PNG，每个图标最多 8192 字符，再随标签状态传给工作台。图标缺失或解码失败时显示地球。图标请求沿用 Chromium 对网页的图片加载策略，页面内路由变化保留图标，网页更换图标后更新显示。

```text
┌──────────────────┬──────────────────────────────────────┐
│ Cage             │ 网页 A × │ 网页 B × │ 文件 · A × │ + │
│ 工作台           ├──────────────────────────────────────┤
│ 浏览器           │ ←  →  ↻  地址栏                      │
│ 下载             ├──────────────────────────────────────┤
│                  │                                      │
│ 项目           + │             当前工作内容             │
│ ▾ 项目 A    ↗ >_ │                                      │
│     终端 1       │                                      │
│ ▾ 项目 B    ↗ >_ │                                      │
│     终端 2       │                                      │
│                  │                                      │
│ 运行状态         ├──────────────────────────────────────┤
│ 设置             │ 网络状态                    停止环境 │
└──────────────────┴──────────────────────────────────────┘
```

未启动时，主界面提供“启动 Cage 环境”，无需选择项目。每份配置只创建和使用一个持久 VM；默认工作区通常为 `~/.claude-cage-workspace`。环境就绪后可直接使用浏览器和终端，再按需打开本地文件夹。重新打开应用继续连接同一环境。

打开项目时，主机通过已有受目录约束的 SFTP 实现，把用户选定的文件夹动态挂载到当前 VM：macOS 使用同名路径，Windows 的 `C:\Users\name\project` 映射为 `/c/Users/name/project`。项目 A 切换到 B 后，A 的共享目录、终端进程、浏览器和编辑器页保持运行。每个项目行右侧有两个按钮：打开图标在 code-server 中打开该目录，终端图标在该目录新建终端。终端工具栏则在当前终端所属目录创建新会话。明确打开的目录继续保留，并在环境重启时恢复共享。所有项目处于同一环境，可以访问其中已共享的目录、工具和账号。

VM 身份固定保存在主机私有的 `environment.json`；最后打开的项目保存在 `workbench.json`，明确打开的目录保存于 `projects.json`。控制服务通过 `/api/status` 的 `projects` 返回完整目录列表，不设最近使用条数限制。Cage 与 Claude Desktop 的项目选择器直接读取同一份 `projects` 列表，支持选择已有项目和明确添加本机目录。`POST /api/projects/open` 由项目系统处理：`add` 表示用户明确添加目录，普通消费者请求只接受已授权目录；`activate` 仅用于保存 Cage 当前项目。接口返回规范化后的主机路径，消费者通过既有映射取得客机路径。终端与编辑器创建请求可携带 `workspace`，只接受默认目录、当前目录及已保存的项目目录；省略时沿用最后打开的项目。前端的目录选择不修改共享授权，也不影响浏览器。首次升级优先保留原有环境的虚拟磁盘；历史其他 VM 不自动删除。项目切换不改变环境身份，也不触发代理探测、网络重检或环境重启。网络与系统配置的修改继续按既有流程验证并重启。

标签支持重命名、置顶、拖动排序和关闭。浏览器标签通过右键或 Shift+F10 打开操作菜单。鼠标移入侧栏终端行或键盘焦点进入该行时，右侧显示置顶、重命名和删除按钮。重命名只改变显示名称；置顶标签排列在各自列表前方，拖动调整同一列表内部的顺序。名称、置顶与顺序保存在本地。⌘1–9 与 ⌘⇧[ / ] 按当前列表的显示顺序切换：浏览器中切换顶部网页，终端中切换同目录的终端。关闭当前网页后激活相邻浏览器页。刷新后重新连接仍存活的终端与浏览器，已结束的进程不因标签恢复而重新启动。

浏览器标签栏与新建按钮垂直居中，标签总宽度随内容区调整，不显示横向滚动条。空间充足时标签最大宽度为 220px；拥挤时当前标签优先保留标题空间，其他标签平分剩余宽度。极窄标签保留可点击位置和悬停标题，右侧搜索入口可按名称或网址查找所有页面。指针拖动时标签跟随移动，相邻标签实时让位；松手保存顺序，Esc 或指针取消恢复原顺序。置顶和普通标签分别在各自分组内排序。

打开至少两个标签后，可将顶部的网页或编辑器标签、侧栏的终端标签拖到内容区。左半区或右半区高亮时松手，标签会在该侧打开。拖动时按 Esc 可取消。每一侧保留自己的页眉。网页有标签栏和地址栏，终端页眉显示项目、会话名和会话操作，终端标签统一在侧栏管理。点击某一侧的“退出分屏”可放大该侧并保留两个标签。关闭一侧的标签后，另一侧恢复为单页。

两个网页并排时，客机 Chromium 将原有标签组成原生分屏。两页分别按自己的可用宽度排版，都能直接点击、滚动和输入。拖动两页之间的分隔线可调整宽度。工作台通过一条远程画面连接显示整个浏览器窗口，地址栏、快捷键、输入法和剪贴板操作跟随当前标签。双网页分屏要求客机 Chromium 155 或更高版本，且两个标签能够在同一浏览器配置中打开。网页与终端并排时，浏览器只占自己的一侧。两个终端并排时，各自按面板尺寸调整行列，切换焦点沿用原终端会话。

地址栏右侧星标与 ⌘D 打开当前网页的收藏编辑框，收藏夹按钮与 ⌘⇧O 打开收藏面板。收藏支持名称、HTTP(S) 地址、单层收藏夹分组、搜索、移动和删除；删除收藏夹将其中的收藏移至未分类。打开收藏通过现有浏览器新建页接口进入 VM，不在主机执行收藏网址。文件编辑器与内部浏览器页面不提供收藏。

收藏由主机控制服务保存在当前配置目录的私有 `favorites.json`，Unix 权限为 `0600`，Windows 使用仅当前用户与 SYSTEM 可访问的显式 DACL；所有项目共用，应用和控制服务重启后保留，不与 Chromium 或外部浏览器同步。`GET /api/favorites` 返回 `items` 与 `folders`；`POST /api/favorites` 通过 `save`、`delete`、`save_folder`、`delete_folder` 操作单条记录，沿用工作台认证与来源校验。修改在专用互斥锁下读取最新文件并原子写入，避免并发新增覆盖其他窗口的收藏。保存失败保留编辑输入，读取失败不覆盖原文件。收藏操作不更改 VM、网络或共享目录状态。

## Claude 入口与终端

浏览器下方提供 `claude.ai` 和 `Claude Desktop` 两个入口。前者在 Cage 浏览器中新建官网页面；后者管理同一份官方 Linux 桌面应用，Chat 与 Code 在应用内切换。Desktop 的安装、登录资料和工作进程均位于当前持久环境中，文件访问沿用已共享的项目范围。Cage 管理安装、启动、状态与关闭，不读取应用会话，也不自动操作其中的任务。

首次进入 Desktop 页面只读取状态，点击“下载并安装”才下载安装包。安装使用 Anthropic 官方 apt 源，校验固定的签名密钥指纹并由 apt 验证软件包；不安装推荐依赖中的 QEMU/KVM，不承诺需要嵌套虚拟机的 Cowork 功能。下载通过[依赖维护通道](managed-proxy.md#依赖安装与更新)使用所选代理，无需业务网络已放行，失败可重试；没有直接联网回退。已安装的应用在进入页面时启动，切换到浏览器或终端保持应用运行；“关闭应用”在提醒保存后停止进程及图形会话，保留登录数据。更新或修复需要先关闭应用。

Desktop 使用编码用户 `cage`、独立的 X11 显示 `:78` 与按需启动的 systemd 服务。虚拟屏幕、窗口管理器、会话总线和应用属于同一服务，停止服务时一起回收。现有浏览器保持使用 `cage-browser` 和 `:77`。Desktop 的 VNC 只监听客机私有 Unix socket，经当前环境的 SSH 标准输入输出通道连接工作台，不创建可被自动转发的 TCP 监听端口。工作台沿用认证与来源校验，网页脚本无法调用应用控制接口。浏览器的 `claude://` 回调仅交给正在运行的官方应用；其他外部协议不由该入口执行。系统密钥环保存应用登录状态，由 Cage 使用账户内部密钥自动创建和解锁。Claude 自身的账号登录仍由用户完成。

项目行的终端图标、终端工具栏与新建终端快捷键均打开类型选择框。普通终端提供 shell；Claude 终端在所选项目中新建交互 shell，并运行设置中的启动命令，默认 `claude`。命令支持参数及单行 shell 表达式，仅在客机执行；退出 Claude 后返回 shell。命令保存在私有 `workbench.json` 的 `claude_terminal_command` 字段，留空恢复默认，拒绝换行、NUL 和超过 4096 字节的输入。保存不重启环境，也不修改现有终端；刷新或重连不会重复执行启动命令。

浏览器将 `claude://` 链接成功转交给正在运行的 Claude Desktop 后，工作台自动显示 Claude Desktop。转交失败时保持当前页面；该通知只表示应用接收了链接，登录是否成功由 Claude 自身显示。客机打开链接的脚本通过浏览器服务的认证接口 `/desktop-focus` 发送通知，现有浏览器事件流以 `desktopFocus: true` 传递一次切换请求。通知不包含回调链接和登录凭据，不保存在浏览器状态中，重连或普通状态更新不会重新触发切换。三个主机平台共用此链路。

应用状态与操作由 `/api/claude-desktop`、`/api/claude-desktop/{install,start,stop}` 提供。安装和启动沿用工作台异步任务。终端创建接口 `POST /api/terminals` 接受普通终端、Claude 终端和账号面板发起的官方登录终端（`shell`、`claude`、`claude-login`）。省略类型时打开普通终端。Claude 启动命令只读取已保存的偏好。

Desktop 默认按内容区域的逻辑像素显示，窗口尺寸和侧栏变化会同步调整虚拟屏幕。工具栏的“显示大小”提供 75%、90%、100%、110%、125% 和 150%，默认 100%；较小的值可显示更多内容，较大的值放大文字和控件。选项在按钮下方浮出，展开和收起时工具栏高度与桌面区域尺寸保持不变。偏好保存在当前工作台的本机存储中，调整立即生效，保持应用和画面连接。

尺寸调整与其他客机控制脚本共用 SSH 执行入口，在客机内明确使用 `/bin/bash --noprofile --norc -c`。SSH 登录仍经过用户的默认 shell，控制脚本的重定向和错误处理由 Bash 执行，避免 zsh 中的 mise 初始化状态使尺寸锁创建提前返回失败。脚本整体经过 shell 引号转义，三个主机平台共用同一执行方式。

应用以 `--force-device-scale-factor=2` 启动；虚拟屏幕宽高为内容区域的 CSS 尺寸乘以 `2 / 显示大小`，noVNC 将画面等比适配回内容区域。虚拟屏幕每边最多 8192 像素，超过上限时按同一比例缩减宽高。尺寸提交串行执行，快速调整窗口时以最新尺寸为准；失败后最多自动重试三次，持续失败显示“重试调整”。macOS、Windows 与 Linux 共用此显示链路。应用启动缩放参数在下次打开应用时生效，工具栏的显示大小无需重启。

## Claude Code 账号面板

“设置 → Claude 账号”有两个入口。环境就绪后，Cage 在客机用户的主目录调用官方 CLI 检查默认登录。检测到订阅时展示邮箱，用户点击“加入调度”后，新的工作台终端才可按账号池策略分配到该身份。加入时会重新核对邮箱和组织，避免用户看到 A 时点击，实际加入的却是 B。没有任何已登记账号时，旧的 Claude 终端入口继续沿用环境原有登录。

“登录新账号”使用独立的配置目录打开官方登录终端，用户在临时浏览器中完成授权。成功后按邮箱登记，无需预填名称，后续可以设置备注。工作台只记录身份和额度摘要，订阅凭据由 CLI 自行管理。

默认目录同一时间只代表一种身份。从 A 改成 B 后，A 的原记录不再用于分配新终端，旧终端仍标记其启动时的账号，B 不继承 A 的参与状态或额度。已有 CLI 进程如何处理外部登录变化由 CLI 决定，继续使用前应确认身份。独立登录各有自己的目录，同时保留多个订阅时更适合使用这个入口。Desktop 的登录不参与发现和调度。

把一个账号暂停后，它的现有终端可以继续工作或断开后重连，下一次新建终端会从余下的账号中选择。所有账号停用、登录失效或额度窗口用尽时，创建会显示原因。已有安装在尚未添加任何账号时继续使用旧配置目录。账号暂停不执行登出，也不删除历史。

每个账号以 Claude Code 的像素角色 Clawd 标识。卡片内的 `5h` 和 `7d` 分别显示已用百分比和距重置的时间。打开账号面板会启动一次额度查询，短时间内重复打开可复用最近的检查。点击“检查状态”会立即检查指定账号。同一身份的并发请求共用在途查询，账号较多时限制并发。列表轮询和倒计时本身不向 Claude 发起新查询。

额度由官方 CLI 的 `/usage` 控制接口提供，命令只查询用量，不发送模型提示。账号身份在查询前后分别核验，身份改变时丢弃本次结果。上次查询时间与每个窗口最近读到数值的时间分开记录。只有一个窗口返回时，另一个保留上次读数。没有数据、查询失败或环境离线时显示相应原因。窗口已过重置时间的旧值只能作为历史参考，不能代表新窗口的用量。受管会话的状态行仍可补充额度读数。账号列表独立滚动，添加入口保持可见。

调度绑定于新建的工作台终端。Cage 重连时复用原进程，不会将一段对话或未完成的工具调用自动搬到另一个订阅。同一项目五分钟内重开，负载和额度接近时优先复用原账号。会话历史按 CLI 配置目录保存，`--continue` 在本次分配的目录中找对话。复用普通终端默认登录也会沿用该目录的历史。独立命令行和绕过受管启动器的自定义命令不参与调度。[数据来源与集成取舍](../research/2026-11-04-claude-account-pool.md)

## 主机输入法

浏览器与 Claude Desktop 共用主机输入法接入：主机负责拼音和候选词，客机应用在自己的输入框内绘制组合文字。选词确认、更新和取消分别传递；普通按键与文字传递共用 noVNC 输入队列，确认后的回车必须等待文字提交完成。全角问号 `？`、逗号等直接产生的字符走文字通道，避免有限的 X11 按键映射丢失字符。Desktop 的兼容粘贴路径会暂时释放远端已按下的修饰键，完成 Ctrl+V 后恢复，保证按住 Shift 输入问号时行为正确。

每个客机图形会话有独立的 IBus 输入桥与权限为 0600 的 Unix socket。浏览器的会话总线只允许 IBus portal 激活；Desktop 沿用自身的会话总线与密钥环。控制请求通过现有认证服务的 `POST /api/input` 进入，不增加网络监听端口。浏览器服务直接访问自己的输入桥，通过固定 sudo helper 把 Desktop 请求交给主用户的输入桥。文字不写入日志、诊断包或状态文件。

输入协议的 `target` 为 `browser` 或 `desktop`，`id` 为活动浏览器标签标识或 `desktop`；`mode` 为 `status`、`begin`、`update`、`commit`、`cancel`。开始组合时绑定客机输入上下文和随机组合会话标识，更新附带递增序号。选段范围采用 UTF-16，下游转换为 IBus 字符索引。目标失焦、标签切换、过期或重复的提交被拒绝；用户点击另一个输入框前先取消组合。程序主动改变焦点时，应用可能按自身原生规则确认已有组合文字，迟到的确认不会进入新输入框。

活动组合通过状态请求续期，断连后十秒内清理未确认文字。文字光标坐标来自客机输入上下文，按实际画布位置和像素比例转换；主机窗口移动由各平台原生坐标转换负责。macOS 使用 AppKit 文本客户端，Windows 使用 Win32 原生编辑控件与 IMM，Linux 使用 GTK 输入上下文。原生接入仅在当前远端输入框确认可用时启用；密码框、未完成组件更新的环境等继续使用已有的确认文字输入方式。

实现和验收范围见[输入法实施记录](../test-reports/2026-11-04-native-ime/progress.md)。三平台构建通过与真实系统输入法验收分别记录，不能互相替代。

## 声音输出

浏览器、Claude Desktop 和环境内其他程序的声音通过工作台在本机播放，输出设备由本机系统选择。底部提供静音和音量控制，偏好保存在当前工作台的本地存储中。首次播放如果受到 WebView 自动播放限制，点击页面或“启用声音”即可继续。切换标签、项目或设置页保持声音；静音、停止环境、锁定账户及退出应用关闭播放连接，重新连接从当前声音开始。

客机的 `cage-audio.service` 仅加载虚拟输出 `cage_output` 及其 monitor，通过限定用户组的 Unix socket 接受应用音频，不加载麦克风或物理设备。浏览器与主用户通过统一的 PulseAudio 配置连接该设备。工作台 `GET /api/audio` 返回固定格式或建立 WebSocket，沿用主机来源、会话和账户认证；每条播放连接经现有 SSH 通道运行固定的 monitor 采集命令。账户访问上下文取消会结束音频请求，客户端断开会结束对应采集进程。每个控制服务最多接受四条音频连接，不增加客机网络监听端口。

传输格式为 48 kHz 双声道 16 位小端 PCM，每条消息通常包含 20 ms 音频。AudioWorklet 适配本机采样率，起播缓冲为 60 ms，缓存上限为 250 ms；积压或中断后清理旧音频。声音输出独立于业务外网放行，依赖安装使用维护通道。macOS、Windows 和 Linux 共用后端及 Web Audio 播放器，不申请本机麦克风权限。

## 设置页

设置占据完整窗口，左侧分类为账户、通用、外观、网络与代理、IP 变化规则、时区与语言、环境与恢复；右侧显示表单，底部固定保存区。离开未保存的表单需要确认，保存失败保留输入。返回工作台保留选中的标签与终端，并恢复可见浏览器画面的连接。

通用页提供浏览器默认网站，缺省为 `https://www.bing.com/`。该偏好保存在 `workbench.json` 的 `browser_home_url`，只接受不含认证信息的 HTTP(S) 网址；保存同步至客机浏览器，无需重启 VM 或终端。工作台新建网页、浏览器最后一页关闭后的补充页使用这个地址；连接时将恢复的空白页和 Chromium 内置新标签页转到该地址，已有普通网页继续保留。

网络表单区分已配置值与真实探测结果。代理密码保持遮蔽，留空表示保留；探测结果提供 IP、位置和检测时间。自动时区和语言设置说明来源与应用时机。项目选择放在主界面，环境与恢复页只展示共享目录和配置恢复操作。

网络与代理页提供[内置代理](managed-proxy.md)的节点、订阅、连接和诊断入口，节点管理器是唯一出口来源，DNS 单独配置并经当前节点转发。节点切换撤销旧连接和检测授权，保留终端进程；更换本地端口需要重启环境。公网 UDP、IPv6、ICMP 持续阻断。

## 视觉与交互

外观以可独立配置的浅色、深色主题组织，支持跟随系统切换。主题包含强调色、背景、文字、对比度、界面及代码字体和侧栏透明度。可选的元素颜色覆盖用于侧栏、工具栏、文字层级、输入、边框、按钮、交互与状态；终端另有背景、前景、光标、选区及完整 ANSI 颜色覆盖。未覆盖的颜色继续由基础色和对比度推导，恢复自动颜色即删除对应覆盖。字号在界面层统一缩放。标准侧栏宽 248px，较窄窗口使用 224px；设置正文最大宽度 720px。原生窗口与终端跟随当前主题，VM 内的编辑器及网页保留自身外观。

内置主题目录统一维护主题系列、分组、用途说明及浅深变体。Codex、Solarized、Ayu 的既有标识与默认配色保持兼容；新增编辑器、阅读及无障碍搭配只在用户选择后应用。预设切换整体复制配色及终端色板，删除上一个预设或自定义留下的颜色覆盖，保留用户字体。高对比与蓝橙配色明确启用不透明窗口；切换回其他主题后可通过“半透明侧栏”自行调整。

无障碍预设以可计算的颜色对比作为验收依据：蓝橙配色的主要文字、辅助文字、链接、状态文字和终端 ANSI 文字对其使用背景达到 4.5:1，高对比配色达到 7:1；焦点和边框对相邻背景达到 3:1。对比度检查覆盖未编辑的内置配置，用户改色后不再保证这些阈值。该检查不代表整款应用的 WCAG 合规认证。成功、警告和错误继续通过不同图标及文字表达；蓝橙配色用于减少红绿依赖，不承诺适用于所有色觉差异。

外观由控制服务独立保存至 appearance.json，前端自动提交，修改失败保留输入并允许重试。读取、保存和本机 Codex 导入分别通过 GET /api/appearance、POST /api/appearance、GET /api/appearance/codex 完成，沿用工作台认证。外观操作不走环境配置应用流程，不重启 VM 或终端；本机导入只复制当前偏好，不创建持续文件监听。

自定义主题库与当前外观一同保存于 appearance.json，最多 50 项。每项具有独立标识、名称及浅深两套主题快照；应用主题只替换两套主题，保留模式、字号和交互偏好。修改当前配色不会自动改写已命名主题，用户需明确选择更新或另存。删除主题仅移除快照。Codex 同步保留此主题库。

主题文件契约为 `{format: "cage-theme", version: 1, name, lightTheme, darkTheme}`。每套主题包含 `preset/accent/surface/ink/contrast/opaqueWindows/fonts`，以及可选的 `colors` 和 `terminal` 颜色表。前端在导入前严格校验版本、字段、字体、六位 HEX 颜色与 256 KB 文件上限；后端对当前主题及全部快照再次校验，未知颜色键、无效颜色、重复标识或超限主题库均不得替换已保存文件。外观保存请求上限为 512 KB。

macOS 的 `importTheme/exportTheme` 原生操作仅接受受信任工作台主框架调用，通过系统文件窗口读写 UTF-8 JSON。Windows 桥接执行相同操作；浏览器使用文件输入与 Blob 下载。取消文件窗口不改动外观，导入同名主题分配新标识，导出内容只含主题配置。原生标题栏跟随当前侧栏颜色，已有终端直接更新 xterm 主题而不重连。

按钮按下即时反馈，项目列表在 180ms 内展开，设置页在 160ms 内进入；减少动态效果模式下直接显示最终状态。工作台终端保持连接。浏览器画面不可见时关闭显示连接，重新可见时重连；浏览器进程、页面、下载和登录状态继续保留。原生窗口隐藏、最小化或关闭也会暂停显示连接，单纯失去键盘焦点不触发暂停。

主要验证视口为 1280×850 与原生最小窗口的内容区 820×558。更窄页面可收起侧栏；设置表单独立滚动，保存操作持续可见。环境连接正常且外网放行仍有效时，品牌区、工作台和状态栏显示绿色带对钩盾牌，并提供状态文字。连接中断、检查中、网络关闭或放行过期时撤销绿色标记；VM 运行但浏览器连接未就绪时显示恢复入口。

界面保留实际网络状态、项目路径和失败原因，日志与详细检查按需打开。

底部状态栏显示当前代理节点到 `www.gstatic.com/generate_204` 的 HTTP 延迟，单位为毫秒。环境运行且没有配置任务时立即检测，之后每 30 秒更新；点击延迟可重新检测。节点或配置版本变化后丢弃旧读数，停止或控制连接中断时显示“延迟 —”，检测失败显示“延迟不可用”。测速沿用内置核心的节点检测接口，不启动代理、不改变节点和外网放行状态；延迟成功不代表环境已获准联网。

## 模块职责

Linux 原生窗口使用 GTK 3 与 WebKitGTK，Windows 使用 WinForms 与 WebView2，macOS 使用 Swift 与 WKWebView；三个平台消费同一 `cage desktop --json` 入口和原生桥协议。Windows 使用 QEMU/WHPX 与 Windows ConPTY，Mac 使用 Apple 虚拟化与 POSIX PTY，客机软件及代理出口约束共用。Linux 使用 QEMU/KVM 与 POSIX PTY，更新通过系统安装包手动完成。平台构建与边界见 [Windows 指南](../windows.md)和 [Linux 指南](../linux.md)。

主机控制服务管理配置、VM 生命周期、会话与只通向该配置唯一 VM 的连接。前端只调用这个服务。终端在 VM 的 SSH 会话中执行；浏览器控制器和 Chromium 在 VM 内运行。编辑器页面也通过 VM 浏览器呈现，避免将来自 guest 的任意网页脚本作为主机控制页面加载。

应用窗口仅加载本机工作台。外部地址统一交给 VM 浏览器；所有网页与编码进程的网络仍由现有 VM 外代理出口接管。

Chromium 通过继承的私有调试管道接受标签与导航命令，不开放 CDP 端口。网页由用户手工操作，启动时关闭 Blink 的 `AutomationControlled` 标记，避免仅因工作台控制管道而向网页报告自动化模式。浏览器服务停止时，先由控制器通知 Chromium 保存标签和配置后退出，再清理剩余子进程。此设置保留浏览器控制与登录态，不保证第三方网站的人机验证一定通过。

当前标签的 `back`、`forward` 可用状态同时包含在 `/tabs` 响应和 `/events` 快照中。完整页面导航、页面内历史变化和标签激活都会刷新 Chromium 的导航历史；过期的异步查询结果不会覆盖较新的状态。工作台只有在状态所属标签与当前标签一致时才启用前进、后退按钮，实时推送连接正常时无需轮询标签接口。macOS、Windows、Linux 共用此逻辑。

## 验收重点

1. 从应用启动到可操作，无需查终端找端口或复制访问密码。
2. 多网页/多终端切换时状态保持，关闭和恢复行为可预期。
3. 网络和系统设置清晰区分草稿、验证结果及已应用值；失败保留输入和原配置。
4. 代理断线时真实请求失败，控制台仍可操作并支持重试；IP 自动时区只使用代理出口位置。
5. 只将默认工作区和明确打开的项目文件共享给 VM；控制会话、主机代理凭据和主机 API 不向 guest 网页开放。
6. 在 1440×900、较窄窗口及放大文字时检查标签、表单与主要操作的可读性。

## 连接与状态约定

日常入口免密。App 持有主机私有启动密钥，通过 localhost 换取有效期 60 秒的一次性入口，再建立 HttpOnly 会话；浏览器和编辑器的内部凭据由工作台管理。链接消费后从地址栏移除，不能重复使用。直接打开一个未认证的控制地址会要求从 App 或启动器进入，不提供人工密码表单。

虚拟显示由 Xtigervnc 提供，直接监听仅限 guest 私有 Unix socket；X0tigervnc 负责文本剪贴板与显示传输。Chromium 以普通全屏模式运行，隐藏原生浏览器栏并允许用户通过 F12 打开开发者工具；kiosk 模式会禁止开发者工具。轻量窗口管理器让 Chromium 随显示区域调整，不提供桌面壳。工作台通过浏览器控制器调整显示模式，以 2 倍像素呈现；画面连接断开时按有上限的间隔重试，不因此重启 VM 或终端。

### 网页复制按钮

用户在 Cage 浏览器点击复制按钮时，客机观察该页面原生复制 API 的完成结果，将这次操作的纯文本传给本机。支持 `Clipboard.writeText`、单项 `Clipboard.write` 的 `text/plain`，以及 `execCommand('copy')` 中明确设置的文本和普通输入框的选中文字。需要浏览器确认用户激活，页面、工作台画面和本机窗口均须处于当前焦点。文字上限为 65536 个 UTF-16 码元；富文本、图片和无法确认准确文字的 DOM 选区通过现有复制快捷键或文本传递面板处理。

工作台在鼠标输入发送前通过 RFB 输入队列确认客机已收到 `/copy-context` 的随机操作标识。复制 API 开始时保存该标识，完成后在当前 `/events` 连接发送一次 `clipboard` 命名事件，数据为 `{id,text,context}`。工作台失焦、切换页面或重连会撤销旧标识，因此切回同一标签也不会接受旧操作的迟到结果。

复制内容不写入标签快照或持久存储，重连不会重复发送。主机转发保持原文，工作台核对来源标签、操作标识和输入焦点后调用三平台共用的 `clipboardWrite` 原生接口。普通点击、拖选或无关的 RFB 剪贴板通知不能授权这条写入路径。已有网页如果改写了观察所需的浏览器 API，当前文档会跳过安装，刷新后在页面脚本之前安装。

### 图片与文件输入

工作内容区接受本机截图、复制的文件和文件拖入，地址栏及设置表单保留本地输入行为。截图使用图片粘贴；文件保留原名与字节，单个上限 2 GB，一次最多 100 个。网页拖入交给落点，文件粘贴按当前焦点模拟拖入；Desktop 将文件放入私有图形会话剪贴板并请求当前输入位置粘贴，目标须支持文件附件。终端接收经过 shell 引号处理的客机文件路径，不自动提交命令。

macOS、Windows、Linux 的 `clipboardReadContent` 原生操作在明确粘贴时返回 `{png: base64}`、`{text: string}` 或 `{fileSelection: string, count: number}`；原有 `clipboardRead` 文本契约保留。文件句柄由原生层保存十分钟且仅使用一次，本机路径不交给网页。`chooseUploadFiles` 返回相同句柄，`uploadHostFiles` 通过独立原生进程读取所选文件并流式传入已建立的上传窗口。

`POST /api/input/files/start`、`finish`、`cancel` 管理文件批次，`POST /api/input/files/{target}/{id}` 接收二进制流，沿用会话、来源及账户解锁校验。浏览器批次绑定标签，提交时核对活动标签；Desktop 批次由私有会话服务管理；终端标识必须对应存活会话。失败的浏览器或 Desktop 批次不提交部分附件。终端已经保存的附件保留，失败时不插入部分路径。

`POST /api/input/image` 接收 `png`、`target` 和 `id`，沿用会话、来源及账户解锁校验。目标为 `browser`、`desktop` 或 `terminal`；浏览器必须提供活动标签标识，终端必须提供存活会话标识。每张 PNG 最大 20 MB、4000 万像素，控制服务解码校验后才交给客机。浏览器通过已有受认证控制通道执行，标签检查和图片输入与标签激活共用操作队列；Desktop 和终端通过 SSH stdin 传入图片，不把图片或主机文件路径放入命令参数。

客机图片助手以目标应用用户运行。网页使用 `cage-browser` 的 `:77` 显示，Desktop 使用 `cage` 的 `:78` 显示及其 Xauthority。GTK 提供 `image/png` 剪贴板并处理大图片的分段传输，xdotool 发送粘贴按键；收到目标的数据请求后返回。剪贴板所有者最多保留 120 秒，被替换后留出 10 秒完成已有传输。终端附件使用随机文件名写入 `~/.local/share/cage/attachments/`，权限为 `0600`，目录为 `0700`，不自动清理仍可能被任务引用的图片。Cage 的图片传递不借助外部存储服务，也不扩大主机目录共享范围；目标网页或应用可按自身行为上传附件。

前端在异步读取、转换图片前保留输入队列位置；图片失败会取消已排在其后的回车等输入，避免提交缺少附件的内容。切换标签或断开连接时，尚未发送的输入取消。接口成功表示图片已传入应用剪贴板或保存为客机文件；目标应用是否将它接受为附件仍由应用自身决定。反向图片复制与旧版独立 noVNC 页面不属于此接口。文件输入使用上述独立流式接口。

自动时区查询通过已选代理完成。应用配置前验证，随后停止环境、保存前一份配置并重启；探测失败保留原配置。运行中不会因定期位置探测自动重启。用户选择恢复配置时，同样明确提示终端中断，并启动恢复后的环境。按键偏好单独保存，不重启环境。

共享下载先存入 guest 私有目录，完成后以编码用户权限统一写入 Cage 环境默认工作区的 Downloads。同名文件不覆盖，路径与符号链接受到检查。终端通过专用 SSH 连接进入 guest，禁用本机转义、本机命令、代理转发及宿主环境继承。工作台刷新可以连接仍在运行的会话；控制服务或 VM 重启后的旧终端不能复原。

下载列表区分下载中、保存中、已保存、失败和已取消。只有完整文件在共享目录中发布后才显示已保存；写入失败保留客机源文件，可在修复空间或共享连接后重试。状态原子保存在浏览器私有目录，控制器恢复后只对已完整下载且源文件仍在的项目提供保存重试；下载被中断时需要从原网页重新下载。列表保留最近 50 条结束记录，最多同时处理 50 个未结束下载，保存过程串行执行。成功保存后清理对应客机源文件；清理失败显示提示，已保存文件保持可用。

侧栏“下载”与浏览器工具栏提供同一下载列表。工作台观察到下载完成后，通过三平台系统保存窗口提供另存为；上传选择尚未结束时延后弹出。取消另存为保留默认位置的文件，历史记录不会在应用重开时反复弹窗。用户可以打开文件、在文件管理器中显示位置，或再次另存为；操作系统使用对应文件的默认应用。文件不会在下载后自动打开。

本机保存由原生桥调用 `browser-file --json save|open|reveal` 完成。浏览器页面只提供下载标识与建议文件名，目标路径来自系统保存窗口；HTTP 接口不接受任意本机读写路径。控制接口按下载标识检查已完成记录，读取默认工作区中的文件，或在共享保存失败时从客机按标识流式读取完整源文件。另存为先写目标目录中的临时文件，核对传递长度并同步到磁盘后原子发布；失败保留原目标文件。默认下载位置和另存为位置分别按记录保存于主机私有 `browser-downloads/`，用户选择的位置优先，停止 VM 后仍可查看，界面最多返回最近 100 个本机位置。来源、账户及会话校验继续生效，账户锁定会取消进行中的文件传递。

网页的标准文件输入使用 CDP 拦截选择请求。每个请求绑定标签、会话和原输入节点，工作台通过三平台原生桥调用本机系统选择器；普通浏览器访问工作台时使用 HTML 文件输入。文件通过受认证的 `POST /api/browser/files/uploads/{id}` 流式传递，保留原始字节和文件名，单个上限 2 GB，多选最多 100 个。全部文件到达后才设置原网页的文件输入；取消或导航使旧请求失效，失败批次不提交部分文件。客机临时文件权限为 `0600`，目录为 `0700`；已提交文件保留到原文档导航、标签关闭或浏览器控制器重启，以支持网页延后读取 File 对象。网页自身的上传、格式校验与账户权限由网页处理，Cage 不代替网站提交消息或请求。

Claude Desktop 的私有 D-Bus 会话运行 `org.freedesktop.portal.FileChooser` 服务；应用启动时要求版本 3 的文件选择接口。工作台读取待选请求，再调用本机选择器；选择结果经现有 SSH 通道传入会话专用 Unix socket，成功后向原调用者返回客机文件 URI，取消时返回取消响应。普通文件选择通过上传副本传递；文件夹请求打开 Cage 的统一项目选择器，直接选择已有项目，或通过“添加本机项目…”完成目录授权与动态共享。Claude 只消费已授权项目，不保存另一份共享列表，也不修改 Cage 当前项目或其他消费者的会话。项目打开、重新连接和目录交付与环境启停共用操作锁。共享完成后，控制服务检查所选目录已在项目列表中，再按主机平台映射为客机路径并返回文件 URI。取消选择返回取消响应，未授权或未挂载的目录不能交给应用。上传副本保留到 Desktop 图形会话重建，以支持应用延后读取，不扩大主机目录共享范围。

Claude Desktop 的 `SaveFile` 请求先取得客机私有下载位置。Chromium 下载在临时文件重命名后完成；直接导出在实际写入并关闭文件后完成。创建空占位文件不算下载成功。完成文件使用浏览器已有的原子复制规则发布到默认工作区的 Downloads，再进入同一个下载列表和三平台本机另存为窗口。取消另存为保留默认位置，文件不会自动打开。下载失败显示原因；已完整写入的源文件可重试保存，进程重启后未确认完整的下载需要重新发起。Desktop 私有下载记录保存在编码用户的持久目录，只公开最近 50 条结束记录；源文件保留，以兼容应用再次读取保存位置。工作台仅接受默认工作区 Downloads 下经过文件名校验的完成记录，不接受客机提供的任意主机路径，也不把浏览器控制凭据交给 Desktop。

编辑器由独立系统服务监督，进程异常退出时自动重新启动。工作台的编辑器恢复操作只重启该服务并重新加载项目页面，保留 VM、浏览器和工作台终端。迁移旧版编辑器时，先核对用户、安装目录、Cage 私有配置和监听参数；无法确认身份的进程不自动停止。

## 作业与后台监测

启动、停止、设置应用和组件更新由工作台的私有作业管理器统一准入与串行执行。HTTP 请求只提交操作并返回作业状态；自动代理恢复与订阅刷新直接使用同一提交入口。页面请求结束不会取消已接受的作业。

停止操作可以取消正在执行或等待执行的旧作业。重复停止返回同一作业；停止过程中请求退出账户，会在该次停止成功后锁定账户，失败则保留登录状态。进度与日志绑定执行时的作业身份，已被替代或结束的作业不能覆盖后续结果。设置操作在准入时记录人工暂停代次，后发生的暂停继续生效。

控制服务拥有作业、监测和活动请求的生命周期。受控退出先封闭准入，取消在途操作并关闭 PTY，再等待任务、订阅与传输循环完成，释放项目共享、浏览器连接和受管代理，最后释放配置锁。窗口关闭仍保留后台，VM 磁盘与持久配置保持不变；停止环境和空闲接管继续遵守各自条件。职责位置、回收顺序与平台边界见[控制服务职责](control-service.md)。

## 更新与后台接管

应用启动后自动检查更新，运行期间每六小时重查；失败后每五分钟重试，隐藏窗口时暂停检查，恢复显示后按到期间隔重查。正常状态不显示入口，发现新版时在左下角显示金色圆形下载按钮，悬浮说明目标版本及停止环境、重启的影响。用户保存工作后点击一次即可开始，不显示更新卡片；下载时按钮显示环形进度与百分比，校验及安装时显示忙碌状态。失败显示原因并保留重试入口。Linux 使用系统安装包更新，不显示自动安装按钮。

点击后通过所选受管代理下载 Release 安装包并核验摘要、应用身份及平台签名：macOS 检查同一 Developer ID Team 与 Apple 验证结果；Windows 检查 Authenticode 信任链、相同发布者公钥和安装器版本。通过后自动停止环境、安装并重启，不再二次确认；代理失败无直连回退。安装或新工作台启动失败时尝试恢复旧 App，无法恢复时保留备份和失败信息。ad-hoc 或未签名开发构建不进入自动安装流程。

更新源为公开 GitHub Releases 接口，不需要 GitHub 凭据，也不读取浏览器登录会话。访问失败时显示原因；草稿、附件缺失或非公开发行物不能作为可用更新。首次安装使用对应平台的 macOS DMG、Windows EXE 或 Linux DEB。macOS 与可信签名的 Windows 版本由应用内更新器检查和下载；Windows 未签名预览版和 Linux 系统包手动更新。

应用启动通过私有启动密钥核对正在运行的控制服务。身份包含完整版本、当前可执行文件的 SHA-256 和控制协议号；文件摘要在进程启动时固定，同版本号的不同构建也能区分。相同构建复用后台；不同构建只有在没有运行环境、作业和存活终端时才自动接管。接管期间拒绝新任务，停止独立代理并优雅退出控制服务，然后由新程序取得同一配置的控制锁。

已有工作时，原生窗口显示“更新待完成”，可明确打开现有环境保存文件，也可在保存后选择停止环境并完成更新。连接旧后台时，窗口标题和关于窗口持续标明更新未完成，不能只用新 App 的版本号代表全部运行组件。

不支持版本握手的旧控制服务需要一次明确的停止与迁移操作。启动器使用认证会话提交停止，确认同一任务成功、环境停止和终端关闭，再核对进程所属用户、可执行文件、完整启动参数、工作目录、监听端口和启动时间后发送退出信号。身份变化、停止失败或退出超时都会中止更新，不发送强制杀死信号。此兼容操作仅支持 macOS，普通启动不会执行。

安装器共用 `cage prepare-update --json`：空闲后台退出后返回 `prepared`，存在运行环境时返回 `stop_required`；安装器继续调用 `prepare-update --stop --json` 完成停止与退出。单次更新点击已授权该停止操作，安装器不再弹出确认。失败以非零退出码和 `error` 状态返回。该入口不启动新后台；安装器替换应用并重新打开后，由常规启动入口接管。

## 持久环境的组件与工具版本

应用与 Linux 磁盘分别升级。Cage 的浏览器控制器、显示服务、编辑器服务和下载辅助程序以嵌入资源的统一摘要标识；只有完整启动脚本成功后，才向客机写入 root 所有的组件清单。工作台连接时读取该清单，缺失、协议不兼容或摘要不符都会显示需要更新，不能仅因健康检查成功就把旧组件标为就绪。

“更新环境组件”在现有 VM 中重新应用幂等脚本，重启浏览器与编辑器相关服务，保留磁盘、项目、账户和工作台独立终端。操作前需要保存浏览器和编辑器中的修改；编辑器内的集成终端可能结束。脚本失败时清单保持无效，用户可查看任务结果并重试。已有运行依赖完整时，组件更新可在暂停外网时执行；用户的暂停状态继续保留。

“更新环境工具”是单独的显式操作，需要环境正在运行且组件已经同步。Chromium 使用 Debian 软件源的更新，code-server、mise 和 Claude 使用随 App 固定的最低版本；当前版本更高时保留现有版本。初次安装与后续升级共用固定安装器，下载包核验摘要后才安装。工具更新不重建磁盘，完成后重新启动相关服务并核对组件状态。依赖维护通道不以业务网络放行为前提；更新期间继续维护已有的业务联网检查与短期续租，用户手动暂停外网的状态保持不变，停止环境会取消安装。

`GET /api/environment/versions` 只在用户查看环境设置时读取工具版本，不加入周期状态查询。返回控制服务实际构建、组件的 `current` / `required`、后端判定的 `update_required`、工具实际与最低版本，以及 `tools_update_allowed`。组件与工具更新分别通过 `POST /api/environment/update`、`POST /api/environment/tools` 提交到现有作业队列。应用原生版本来自 App 的版本信息，不能用旧控制服务的版本代替。
